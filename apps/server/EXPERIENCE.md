# 作者体验配置操作说明

## 配置与更新

`EXPERIENCE_CONFIG_PATH`（体验配置文件路径）为空时不开放作者体验。部署时将它设为静态资源目录之外的文件位置；支持当前系统的绝对路径，不依赖本仓库被忽略的规格文档。不要将配置、更新输入或备份提交到 Git。

公告和唯一邀请码通过以下命令更新，不能直接编辑或回滚生成文件：

```text
pnpm run experience:configure --input <受保护更新文件的绝对路径>
```

更新文件只允许 `announcement`（公告）与 `inviteCode`（邀请码）两个可选字段。首次可以只写公告或 `{}`，程序生成随机邀请码；原始码仅在受保护的生成文件内查看，命令不输出它。示例只用于说明格式，不是可用凭据：

```json
{"announcement":"体验说明：额度共享，可能不足"}
```

- 只改公告：不要传 `inviteCode`，原有资格保持有效。公告按原文纯文本展示；主动把当前邀请码写进公告，就允许所有持码者体验。
- 改邀请码：在受保护输入文件填写新的 `inviteCode`；每次显式设置都会生成新授权代际，旧码对应资格立即失效，即使设回曾用值也不复活。
- 默认随机码包含充足随机性。自行选择短码或常见词会降低抗猜测能力；恒时校验不能阻止暴力尝试，本功能不保证共享码仅由指定自然人使用。
- 程序将独立随机的签名秘密、代际、邀请码和公告一并保存。普通更新及服务重启保留签名材料；不要把旧配置备份覆盖回现有文件，否则属于回滚授权状态，不是受支持的恢复操作。

更新命令对同一目标加排他锁，在锁内重新读取旧值，再写临时文件并原子替换。遇到正在进行的更新会明确失败，可在前一次更新完成后重试。若进程崩溃遗留 `.lock`（写锁），先确认没有其他配置更新进程，再由部署人员移除锁；不能在更新仍运行时强行删除。

## 权限与隐私

POSIX（macOS / Linux）上的更新输入、生成配置必须仅部署账户可读写，例如权限 `0600`；生成目录优先 `0700`。Windows 必须通过文件属性的安全设置限制 ACL（访问控制列表），仅部署账户及必要管理员可访问；程序不会把 Windows 的 `chmod` 结果当作 ACL 验证。

拒绝符号链接、非普通文件、损坏 JSON、未知字段及过大输入。错误仅输出固定提示，不输出配置、邀请码、签名材料或敏感路径。配置缺失或读取不确定时拒绝作者能力，不沿用旧配置缓存；不会因此把自带 Key 自动切换为作者 Key。

浏览器资格通过专用安全通道保存，作者 Key 永不下发。正式部署要求 HTTPS；所有作者调用及缓存门禁由后续接线落实，授权接口可用不等于搜索接口已经受到授权保护。

WAY-124 已注册 `GET /api/settings`（公开公告）、`POST /api/experience`（验证邀请码）及 `GET /api/experience/status`（当前资格）。三路成功与错误响应均禁止缓存，普通 JSON 只投影公共 Contract（协议）字段，资格状态不是授权材料。配置关闭时公告为空、资格为假；配置损坏或不可读取时返回固定不可用错误，不沿用旧值。

服务端用独立 HMAC-SHA256（基于散列的消息认证码）签发绑定当前代际的资格，放入 `__Host-wayfinder_experience` Cookie（浏览器凭证），具有 HttpOnly（脚本不可读）、Secure（仅安全连接）、SameSite=Strict（严格同站）、`Path=/`，不设置 Domain（域）。邀请码及签名材料不放入响应正文。浏览器最长保留 400 天是浏览器持久化边界，不是服务端邀请码天数期限；查询仍有效的资格时续存。失败不清除原有 Cookie，仍有效的原资格不因输错新码而丢失。正式部署、生产浏览器及 Safari 使用 HTTPS；本地 HTTP 仅适用于支持安全 Cookie 回环例外的浏览器，不降低 Cookie 属性。

正式部署设置 `PUBLIC_ORIGIN`（可信公开来源），例如 `https://wayfinder.example`。仅接受 HTTPS 纯 Origin（来源），或本地开发的 HTTP 规范回环来源；可带末尾 `/`，不能携带账号、路径、查询或片段。反向代理应保留匹配该站点的 `Host`（主机）头；代码不信任任意 `X-Forwarded-*`。未设置时只接纳明确的 `localhost`、规范 `127/8` 或 `[::1]` 回环地址，且 Origin 与 Host 对应的 HTTP 来源必须精确一致，不放行不同端口、不同协议或不同回环主机名。本地页面经保留前端 Host 的 Vite 同源代理调用 API；其他代理拓扑应明确配置 `PUBLIC_ORIGIN`，不放宽来源规则。

三路校验 Host；声明了 Origin 时要求其匹配可信站点，POST 必须有 Origin。`Sec-Fetch-Site`（请求站点关系）明确为 cross-site（跨站）或 same-site（同站但不同源）均拒绝。签发和续存前再次读取当前配置，防止校验中途改码仍发出旧资格。浏览器提交自己的 Key 仍须由 WAY-125 另接 `x-wayfinder-credentials` 请求头，不混入搜索内容；本项未改变现有搜索接口行为。

基础防滥用限定为严格输入 Schema、有限请求体积、每次有界验证、不公开离线猜码材料，以及默认高熵码。POST 请求体上限为 32 KiB，足够承载已批准邀请码输入边界；非法 JSON、过大输入和不支持的 Content-Type（内容类型）均输出固定脱敏错误。比较采用固定长度摘要的恒时校验，但没有新增用户次数门槛，不能声称抵御无限请求或弱码爆破；需要频率门槛或新依赖时先按规格确认。排队 / 缓存 / 上游调用前的授权门禁由 WAY-125 接通，不提前宣称已经实现。

## 开发与验证边界

配置命令和普通 CI 不发起 Search / LLM（检索 / 大语言模型）请求。测试仅使用临时文件与假秘密，运行不依赖本说明或本地私密规格。真实容量、产品质量、延迟、成本和生产部署需要分别验证，不能用配置单测代替。
