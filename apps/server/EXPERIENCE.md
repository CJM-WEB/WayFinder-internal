# 作者体验配置操作说明

## 部署入口与首次配置

从仓库根目录使用固定的 Node.js 24.21.0 与 pnpm 11.25.0。`.env.example` 是可交付的变量说明；实际 `.env` 和任何受保护配置均不进入 Git。`LLM_API_KEY`（作者 DeepSeek 密钥）、`SERPAPI_API_KEY`（作者搜索密钥）只在服务端使用，不能写进 `VITE_*`（前端构建变量）、静态文件或公告。

1. 为部署账户准备私有配置目录；设置 `EXPERIENCE_CONFIG_PATH` 和 `PUBLIC_ORIGIN`，按下节创建受保护的更新输入并运行配置命令。
2. 执行 `pnpm build`，再执行 `pnpm start`。Windows PowerShell 可使用对应的 `pnpm.cmd`。正式服务通过 HTTPS 同源提供页面和 `/api/*`；反向代理保留与 `PUBLIC_ORIGIN` 匹配的 Host、Origin、专用凭据头及 Cookie / Set-Cookie，并关闭 API 缓存和 NDJSON（逐行 JSON）响应缓冲，使取消与增量结果能及时传递。
3. 在浏览器底部箭头展开“设置”。默认分别填写自己的 Key 并明确保存；缺配置不会搜索。选择作者体验时读取公告、验证邀请码并确认额度提示；保存或验证资格不会调用付费 Provider（服务提供方）。

反向代理、CDN（内容分发网络）及 APM（应用性能监测）的请求采集同样要排除 `x-wayfinder-credentials`、Cookie、Set-Cookie 和邀请码请求正文；不得记录完整请求或上游 SerpAPI 含 `api_key` 的 URL。不要将这些字段放进访问日志、错误页面或支持截图。受保护配置目录也不能经代理的静态别名公开。

## 配置与更新

`EXPERIENCE_CONFIG_PATH`（体验配置文件路径）为空时不开放作者体验。部署时将它设为静态资源目录之外的文件位置；支持当前系统的绝对路径，不依赖本仓库被忽略的规格文档。不要将配置、更新输入或备份提交到 Git。

公告和唯一邀请码通过以下命令更新，不能直接编辑或回滚生成文件：

```text
pnpm run experience:configure --input <受保护更新文件的绝对路径>
```

更新文件只允许 `announcement`（公告）与 `inviteCode`（邀请码）两个可选字段。首次可以只写公告或 `{}`，程序生成随机邀请码；原始码仅在受保护的生成文件内查看，命令不输出它。示例只用于说明格式，不是可用凭据：

```json
{"announcement":"体验说明：额度共享，可能不足"}
```

更新命令必须由同一部署账户、在指向同一目标的 `EXPERIENCE_CONFIG_PATH` 环境中执行。服务管理器注入的环境变量不会自动进入交互终端；本仓库脚本从根 `.env` 读取变量，也可使用受控的进程环境，不要为核对配置而回显秘密或把它们放进命令历史。

- 只改公告：不要传 `inviteCode`，原有资格保持有效。公告按原文纯文本展示；主动把当前邀请码写进公告，就允许所有持码者体验。
- 改邀请码：在受保护输入文件填写新的 `inviteCode`；每次显式设置都会生成新授权代际，旧码对应资格立即失效，即使设回曾用值也不复活。
- 默认随机码包含充足随机性。自行选择短码或常见词会降低抗猜测能力；恒时校验不能阻止暴力尝试，本功能不保证共享码仅由指定自然人使用。
- 程序将独立随机的签名秘密、代际、邀请码和公告一并保存。普通更新及服务重启保留签名材料；不要把旧配置备份覆盖回现有文件，否则属于回滚授权状态，不是受支持的恢复操作。

更新命令对同一目标加排他锁，在锁内重新读取旧值，再写临时文件并原子替换。遇到正在进行的更新会明确失败，可在前一次更新完成后重试。若进程崩溃遗留 `.lock`（写锁），先确认没有其他配置更新进程，再由部署人员移除锁；不能在更新仍运行时强行删除。

公告和邀请码通过上述命令原子发布后，运行中的服务在下一检查点读取新文件，无需重启或刷新浏览器。改动 `.env` 中的路径、公开来源或作者 Key 则需要重新启动服务；普通用户保存设置只影响其后发起的运行。当前队列和缓存属于单个服务进程，本功能没有提供多副本之间的分布式授权或总并发协调。

## 权限与隐私

POSIX（macOS / Linux）上的更新输入、生成配置必须仅部署账户可读写，例如权限 `0600`；生成目录优先 `0700`。Windows 必须通过文件属性的安全设置限制 ACL（访问控制列表），仅部署账户及必要管理员可访问；程序不会把 Windows 的 `chmod` 结果当作 ACL 验证。

拒绝符号链接、非普通文件、损坏 JSON、未知字段及过大输入。错误仅输出固定提示，不输出配置、邀请码、签名材料或敏感路径。配置缺失或读取不确定时拒绝作者能力，不沿用旧配置缓存；不会因此把自带 Key 自动切换为作者 Key。

浏览器资格通过专用安全通道保存，作者 Key 永不下发。正式部署要求 HTTPS；WAY-125 已接入搜索、缓存、队列及上游尝试前的作者资格门禁，单纯得到公开资格状态仍不能替代实际调用时的检查。

WAY-124 已注册 `GET /api/settings`（公开公告）、`POST /api/experience`（验证邀请码）及 `GET /api/experience/status`（当前资格）。三路成功与错误响应均禁止缓存，普通 JSON 只投影公共 Contract（协议）字段，资格状态不是授权材料。配置关闭时公告为空、资格为假；配置损坏或不可读取时返回固定不可用错误，不沿用旧值。

服务端用独立 HMAC-SHA256（基于散列的消息认证码）签发绑定当前代际的资格，放入 `__Host-wayfinder_experience` Cookie（浏览器凭证），具有 HttpOnly（脚本不可读）、Secure（仅安全连接）、SameSite=Strict（严格同站）、`Path=/`，不设置 Domain（域）。邀请码及签名材料不放入响应正文。浏览器最长保留 400 天是浏览器持久化边界，不是服务端邀请码天数期限；查询仍有效的资格时续存。失败不清除原有 Cookie，仍有效的原资格不因输错新码而丢失。正式部署、生产浏览器及 Safari 使用 HTTPS；本地 HTTP 仅适用于支持安全 Cookie 回环例外的浏览器，不降低 Cookie 属性。

正式部署设置 `PUBLIC_ORIGIN`（可信公开来源），例如 `https://wayfinder.example`。仅接受 HTTPS 纯 Origin（来源），或本地开发的 HTTP 规范回环来源；可带末尾 `/`，不能携带账号、路径、查询或片段。反向代理应保留匹配该站点的 `Host`（主机）头；代码不信任任意 `X-Forwarded-*`。未设置时只接纳明确的 `localhost`、规范 `127/8` 或 `[::1]` 回环地址，且 Origin 与 Host 对应的 HTTP 来源必须精确一致，不放行不同端口、不同协议或不同回环主机名。本地 Vite 的 `/api` 必须使用显式代理对象并设置 `changeOrigin: false`，保留浏览器原 Host / Origin；字符串简写默认改写 Host，会导致开发页面的授权及搜索 POST 被拒绝。其他代理拓扑应明确配置 `PUBLIC_ORIGIN`，不放宽来源规则。

三路校验 Host；声明了 Origin 时要求其匹配可信站点，POST 必须有 Origin。`Sec-Fetch-Site`（请求站点关系）明确为 cross-site（跨站）或 same-site（同站但不同源）均拒绝。签发和续存前再次读取当前配置，防止校验中途改码仍发出旧资格。浏览器提交自己的 Key 使用 `x-wayfinder-credentials` 请求头，不混入搜索内容；其结构由公共 `SearchCredentialsSchema` 唯一定义。

基础防滥用限定为严格输入 Schema、有限请求体积、每次有界验证、不公开离线猜码材料，以及默认高熵码。邀请码 POST 请求体上限为 32 KiB，足够承载已批准输入边界；非法 JSON、过大输入和不支持的 Content-Type（内容类型）均输出固定脱敏错误。比较采用固定长度摘要的恒时校验，但没有新增用户次数门槛，不能声称抵御无限请求或弱码爆破；需要频率门槛或新依赖时先按规格确认。

## 搜索凭据与撤销接线

`POST /api/search`（搜索请求）在发送流式成功响应和调用 Provider 前，检查同源、专用凭据头与当前作者资格。缺失头不再默认消耗作者 Key。两服务分别使用自己的 Key 或作者 Key；运行开始后固定本次选择，不修改全局环境变量。搜索正文、图记录、模型提示词与返回事件不包含凭据。

作者资格在缓存命中、全局队列出队、每个 LLM 阶段及每次 SerpAPI HTTP 尝试前复核。改码或无法确认配置时，中止旧作者运行，不再发起后续作者调用；已发送的请求不能保证撤回。双方均自带 Key 的请求不读取体验配置，所以配置缺失或损坏不影响这类请求。

所有请求共享既有 Search 6 / LLM 3 队列及 40 秒运行期限；取消排队任务会释放动态 Adapter 与 Key 引用，不清除其他请求。作者缓存共用一个 4 MiB 有界池，并按授权代际隔离；自带 Key 仅本次运行内缓存，不跨请求保存。生产启动还会检查配置路径及既有祖先的真实位置，拒绝配置实际落入公开静态目录；内容缺失或损坏仍由作者授权检查单独拒绝，不将其误作自带 Key 的依赖。

授权读取也消耗 LLM 阶段预算：队列扣时之后继续按单调截止点扣除鉴权等待，已耗尽时不发起付费调用，不把旧超时额度重新交给上游。请求取消及资格撤销均保留原始中止原因。

## 备份、恢复与失败诊断

配置文件中的签名材料和当前代际必须随同其余配置一起保存在访问受控的备份中；正常重启或迁移使用同一份最新文件即可恢复仍有效的浏览器资格。不要单独轮换签名秘密或手写代际。无法确认备份是否为最新授权状态时，先停止服务，恢复受保护备份后用配置命令显式设置新的邀请码、产生新代际，再启动服务，避免旧备份复活已撤销资格。若文件损坏，停服后先将坏文件隔离到受控存储，配置命令不会直接覆盖无效旧文件。签名材料彻底丢失时，应通过配置命令初始化新的私有文件并让用户重新验证；更换配置路径后重启服务，不能承诺旧资格继续可用。

| 现象 / 公共错误 | 检查与处理 |
| --- | --- |
| `CREDENTIALS_REQUIRED`（缺少凭据） | 在设置中保存缺失服务的自带 Key，或明确确认作者体验；不会自动改用作者 Key。 |
| `CREDENTIALS_INVALID`（凭据或来源无效） | 检查两项来源、专用头、JSON 格式与同源配置；跨站、Host 不符或错误的代理来源均不能放宽校验。 |
| `INVITE_CODE_INVALID`（邀请码无效） | 使用作者当前提供的唯一邀请码，不把原始输入复制到错误记录。 |
| `EXPERIENCE_REVOKED`（体验资格已撤销） | 用当前码重新验证；改回曾用码也必须重新验证，不能重放旧 Cookie。 |
| `EXPERIENCE_UNAVAILABLE`（体验不可用） | 检查路径、普通文件类型、权限 / ACL、JSON、写锁及配置是否关闭；双自带 Key 仍可使用。 |
| 验证后仍无浏览器资格 | 检查 HTTPS、Cookie 属性与同源代理。浏览器清理、限制或拒绝存储后需要重验，不能降低 HttpOnly / Secure / SameSite 属性。 |
| 上游失败或运行中断流 | 依据既有搜索错误和脱敏阶段记录诊断，不猜测一定为额度不足；已发出的上游请求可能仍计费，不自动切换 Key 或重试到成功。 |

## 开发与验证边界

配置命令和普通 CI 不发起 Search / LLM（检索 / 大语言模型）请求。测试仅使用临时文件与假秘密，运行不依赖本说明或本地私密规格。真实容量、产品质量、延迟、成本和生产部署需要分别验证，不能用配置单测代替。
